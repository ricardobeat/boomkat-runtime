Native byte enqueue for direct HTTP stream sources

Engine: boomkat-perf 2bdab09b (main 229e7b7a, plus external string and VM cache work).
Runtime: f73129c plus constant stream checks, then the native controller in this commit.
Compiler: C3 0.8.4 / LLVM 23.1.1; optimized threaded dispatch; Apple M3.
Node v24.13.0; Bun 1.3.13. Client and server share the same machine.

What changed:
Sink.prototype.enqueue is a host function. For ordinary Uint8Array chunks it
validates the controller layout, current constructor/@@hasInstance, current view
length getter and Array.push. It appends through the engine helper (including the
heap write barrier), reserves dense capacity natively and updates the byte count.
Bootstrap configuration is validated and can run only once. Guards precede
observable mutations, including a check for global lexical constructor shadowing. Conversions, altered descriptors/methods,
proxies, readonly fields, unusual prototypes and wake callbacks use the original
JS method. The source pump, microtask order and async/backpressure path are retained.
The remaining setup and source pull code still execute in JS.

Caches resolve against current property storage and validate shape identities,
shape-recycle epochs and prototype links. Mutable global dictionaries get a live
index/flags lookup. Treating the global dictionary as an ordinary shape caused the
initial prototype to fall back on every chunk; that rejected prototype was slower.

For extra chunks the slope falls from about 71–72 to 44–45 VM instructions.
The 8-chunk path drops from about 41 ->33 CALL opcodes, 208 ->168 LDREG copies,

unchanged. Full counters: stream-native-ops.json and stream-native-opcodes-*.txt.

API differences: Node streams use eight res.write calls and end; Boomkat/Bun use
Web ReadableStream. Node precomputes JSON. Node/Bun async handlers await
Promise.resolve after yielding, while Boomkat uses .then. Bun serves files with
Bun.file; Boomkat uses native file.body. Bun is the closer streaming API comparison.
The earlier Web Streams adapter diagnostic for Node is in stream-profile-results.txt.

Validation:
- Optimized and main-engine HTTP suites, including slow clients and disconnects.
- AddressSanitizer HTTP suite plus stream/timer API checks, with leak detection disabled.
- Replaced Array.push, prototype/own length getters, readonly controller size,
  custom @@hasInstance, replaced/accessor global Uint8Array, proxies and invalid
  layouts. Also resizable/detached buffers, readonly array fallback and closed state.
- Readonly array fallback is compared against the existing engine Array.push:
  that engine currently appends before the final readonly length write throws,
  also observed in the saved JS baseline. This change preserves that fallback.
- 1000 repeated stream/promise responses: RSS growth 5.9 MiB, below the 32 MiB bound.
- New C3 source formatted; git diff --check passed.

Reproduction:
  c3c build bkr-perf
  BKR_BIN="$PWD/out/bkr-perf" python3 bench/run.py 2 128
  c3c build bkr-perf-prof

Build targets sequentially: C3 shares temporary C object paths between targets.
