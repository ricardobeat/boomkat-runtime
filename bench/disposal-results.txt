using vs manual try/finally: -6.2% throughput.
awaitusing vs finallyasync: -31.8% throughput.
cached vs manual per-request prepare/finalize: +67.5% throughput.

manual and using both prepare one statement per request, execute it once and finalize.
finallyasync is an async function with await stmt.finalize() in finally.
awaitusing is an async function using the synchronous Symbol.dispose fallback.
cached reuses a statement prepared once at startup; it changes resource lifetime.
These are whole HTTP workloads, not the nanosecond cost of disposal syntax. All
prepare-per-request variants show much higher RSS than the cached case; sampled RSS
does not establish a leak or retained-memory bound. No allocation profile was taken.

Use synchronous using for scope-bound SQLite resources where guaranteed cleanup is
valuable. Keep reusable hot-path statements alive across requests. await using works
for real async lifetimes such as HTTP servers; its one-time lifecycle cost is separate
from per-request throughput. A returned response stream may outlive its handler scope,
so resources needed by that stream must be disposed when stream consumption finishes.
