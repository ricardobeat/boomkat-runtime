Runtime benchmark: boomkat-perf versus local boomkat main

Runtime source: 4255e0c for both binaries. Engine main: 229e7b7a; engine boomkat-perf: 8ef0ab04. Matching O3, single-module, relaxed FP, threaded dispatch and CONSOLE settings. C sources and native uWebSockets library are identical.

Four alternating-order pairs per workload, fresh server for every sample, 1s warm-up +3s measured, wrk -t2 -c128 on loopback. Median per-run results. Latency and memory cells show main / perf. Peak RSS sampled every 100ms during measurement; fresh-process values exclude memory retained by previous workloads. Both binaries passed the HTTP lifecycle/native body suite. All 56 measured runs and warm-ups reported no socket or HTTP errors.

Streaming improved in all four pairs: +5.4%, +5.7%, +5.6%, +5.9%. Other median throughput changes range from -0.6% to +1.1%, which is within ordinary local-run noise. These results measure only the ten engine commits between local main and boomkat-perf; both sides contain the current native runtime response/stream implementation and main already contains the earlier async/promise work.

Raw samples, full wrk output and binary SHA-256 hashes: bench/server-perf-vs-main.json.

Reproduction: c3c build bkr; c3c build bkr-perf (sequential builds), then run /private/tmp/server-perf-vs-main.py.
