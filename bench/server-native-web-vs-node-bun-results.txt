Comparison scope:
- This uses the established server implementations without changing their handlers. It measures these server API workloads, not just VM execution.
- Node uses node:http, switches on req.url and caches the JSON response string. Bun uses an async Bun.serve fetch handler, URL parsing, Response.json, ReadableStream and Bun.file. Boomkat uses a synchronous fetch handler, native common URL/Response paths and deferred results for async operations.
- The file payload is 4096 bytes; echo uploads 1024 bytes; streaming sends eight 1024-byte chunks. The same payload file and load-generator settings are used for all runtimes.
- Near ties such as JSON and timer should be interpreted within run-to-run noise.

Validation of engine main and the fresh runtime:
- Five focused descriptor/mapped-argument tests and all 42 Rosetta cases passed on engine main.
- Runtime built against engine main passed 63 API differential cases, retained Request/Response mutation tests and the full HTTP lifecycle/native body suite.
- Native-path gains, separate contributions and ASAN/forced-GC validation are recorded in bench/native-web-results.txt.
