how-to guide

Configure permissions with flags and boomkat.toml

Scope network, filesystem, environment, and subprocess grants on the command line or in a project config file, and narrow permissions at run time.

Grant and deny permissions with CLI flags

Pass comma-separated allowlists to --allow-<perm>, or omit the list to grant the whole category. --deny-<perm>=list wins over any allow rule, including -A (--allow-all): 

# Scope network to specific hosts/ports and filesystem to specific folders
bkr --allow-net=api.example.com,:8080 --allow-read=./data --allow-write=./out app.js

# Allow everything except cloud metadata IPs
bkr -A --deny-net=169.254.169.254 app.js

# Disable interactive terminal prompts
bkr --no-prompt --allow-net=:8080 app.js

Put project defaults in boomkat.toml

bkr automatically loads boomkat.toml from the entry script's directory (or the path given to --config). Relative paths in the file resolve against the config file's directory. Command-line flags are applied again on top of the file so they always take precedence: 

[permissions]
prompt = false
net = ["127.0.0.1:8080", "api.example.com", "*.cdn.example.com"]
read = ["./public", "./data"]
write = ["./data"]
env = ["APP_*"]
run = ["git"]

When prompt = false (or --no-prompt is set), grants are fixed for the run and macOS applies a Seatbelt sandbox that blocks network, process execution, and file writes outside the grants. Pass --no-sandbox to disable the OS sandbox.

Query, request, and revoke permissions in JavaScript

Use the permissions module to inspect grants or drop privileges after startup initialization: 

import { query, request, revoke } from "permissions";
import { readText } from "file";

const config = JSON.parse(await readText("./secrets.json"));

// Drop read access to secrets.json for the rest of the process lifetime
await revoke({ name: "read", path: "./secrets.json" });

const status = await query({ name: "read", path: "./secrets.json" });
console.log(status.state); // "denied"

Bound execution time with --time-limit

Pass --time-limit=ms to start a watchdog thread that interrupts JavaScript turns exceeding the budget (including top-level module evaluation and synchronous SQLite queries): 

bkr --time-limit=250 --allow-net=:8080 server.js

If an HTTP request handler exceeds the time limit, the server responds with 500 Internal Server Error and keeps serving subsequent requests. Any other runaway turn exits the process with status 1.
