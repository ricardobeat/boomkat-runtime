Scale HTTP servers and run module workers

Offload CPU work to isolated Worker threads, or scale an HTTP server across in-process VMs or multi-process worker pools.

Offload work to a module Worker

Each new Worker(url, { type: "module" }) starts a native thread with its own Boomkat VM, heap, and event loop. The worker inherits the parent's permissions with prompting disabled. Create sum.ts: 

onmessage = ({ data }: MessageEvent<Uint32Array>) => {
  let sum = 0;
  for (const value of data) sum += value;
  postMessage(sum);
};

Spawn the worker and transfer an ArrayBuffer from main.ts:

const worker = new Worker("./sum.ts", { type: "module", name: "sum" });
worker.onmessage = ({ data }) => {
  console.log("Sum:", data);
  worker.terminate();
};

const numbers = new Uint32Array([10, 20, 30, 40]);
worker.postMessage(numbers, [numbers.buffer]);

Run it with read permission for the worker directory:

bkr --allow-read=. main.ts

Scale across in-process VMs with --http-workers=N

Pass --http-workers=N (1–64) to run N server VMs in one OS process. The runtime binds one listener and distributes accepted TCP connections round-robin across the VMs; HTTP keep-alive requests remain on their assigned VM: 

bkr --http-workers=4 --allow-net=127.0.0.1:8080 \
  --allow-read=examples/taskboard --allow-write=examples/taskboard/data \
  examples/taskboard/server.ts 8080 examples/taskboard/data

Each replica evaluates the entry module independently with its own globals and heap. On the main server, await server.ready resolves once all N VMs have joined the listener, and server.workers reports the joined count.

Scale across OS processes with --http-processes=N

Pass --http-processes=N (1–64) to spawn N worker processes behind a native supervisor. The supervisor accepts connections and passes socket descriptors round-robin over Unix domain sockets with SCM_RIGHTS: 

bkr --http-processes=4 --allow-net=127.0.0.1:8080 \
  --allow-read=examples/taskboard --allow-write=examples/taskboard/data \
  examples/taskboard/server.ts 8080 examples/taskboard/data

--http-workers and --http-processes each support one serve() call per entry module and cannot be combined with each other or with serve({ tls }).

Graceful shutdown with await using

The server returned by serve() implements Symbol.asyncDispose. Calling await server.stop() (or exiting an await using server = serve(...) block) stops accepting new connections and drains active responses before closing. Pass server.stop(true) to force immediate termination.
